# Examples

Small plugins, one per part of DAOLib, written to be read and copied from. Each is also a check of its part in the game: `tools\deploy.ps1 -Examples <part>` puts it in its own folder in `bin_ship\daolib\plugins\` with the rest (`-Examples *` for all of them), and each logs what it does to `example_<part>.log` in the daolib log folder (`Documents\BioWare\Dragon Age\daolib\`). They go in only when named, since each changes the game in its own way: `camera/` moves the camera, and would fight another plugin that does. A deploy that does not name one takes it out.

They build with the library when DAOLib is the top-level project (`DAO_BUILD_EXAMPLES`), and each is one `add_daolib_plugin` line in `examples/CMakeLists.txt`, as a plugin in its own repository would be (`dev/PLUGINS.md`).

|---|---|---|
| [`camera/`](camera/Camera.cpp) | Moving the camera smoothly when the player selects another party member: a glide in the tactical view, coming round behind them close in, and never fighting the player's own turning | `dao/CameraMoves.h`, `dao/Camera.h` |
| [`damage/`](damage/Damage.cpp) | Changing combat without replacing a script: the party takes half damage, changed where the scripts hand the new health to the engine, so no script override and other plugins can do the same beside it | `dao/ScriptHooks.h` |
| [`commands/`](commands/Commands.cpp) | Commands starting and ending: the controlled creature's, and anyone's that fail, with how they ended | `dao/CommandEvents.h` |
| [`party/`](party/Party.cpp) | Who the player controls and what the party puts on and takes off, by any cause: each change logged with the creature, the item, its slot and whether the engine did it | `dao/Party.h`, `dao/Equipment.h` |
| [`cooldown/`](cooldown/Cooldown.cpp) | An ability's cooldown as the quickbar draws it: the seconds left and the seconds it was set to, read after each ability the controlled creature uses, then set to two thirds of a long hold | `dao/Abilities.h` |
| [`input/`](input/Input.cpp) | A key of the plugin's own: two actions registered as the game registers its own, one on F11 and one for the player to bind in the controls screen, each press logged | `dao/Input.h` |
| [`options/`](options/Options.cpp) | Settings of the plugin's own in the game's options screen: a section on the Game tab with three checkboxes, one of which refuses every click, a second with a dropdown over a slider with named stops, a third on the Video tab, a fourth the Video tab has no room for, and a fifth on the Online tab with two buttons that each log a press | `dao/Options.h` |
| [`preview/`](preview/Preview.cpp) | Drawing in the world: the game's aiming ring follows the cursor, the in-reach or out-of-reach row by the distance | `dao/Vfx.h` |
| [`animation/`](animation/Animation.cpp) | How long attacks and abilities take: for everyone in a fight, each attack's and ability's times as the library reads them when it starts, and how long it really took when it ends | `dao/Animation.h` |
| [`attack/`](attack/Attack.cpp) | An attack's approach and its steps: for every attack and ability used at another creature, each step of the command with the time the engine gave it and how long it ran; for a shooter, where the library says the approach will stop and where it did | `dao/Attack.h`, `dao/SubActions.h` |
| [`journal/`](journal/Journal.cpp) | The journal: the quests under way and finished, each with its plot, title, group and the entry showing, and the active one, logged whenever any of it changes | `dao/Journal.h` |
| [`dialogue/`](dialogue/Dialogue.cpp) | Conversations: each NPC line, the replies offered, and the replies whose condition hid them, with the plot flag or script that decided | `dao/Dialogue.h` |
| [`world/`](world/World.cpp) | The world's geometry: whether the controlled creature can see what the cursor is on, and what a ray straight down meets, with each hit's collision groups | `dao/World.h` |
| [`speed/`](speed/Speed.cpp) | The game's speed: fights run twice as fast, what the player sees keeping pace with the AI, effects and regeneration | `dao/Clock.h` |
| [`clock/`](clock/Clock.cpp) | The clock effects, regeneration and the scripts' timers run on, held and moved by the plugin: in a fight the controlled creature's time runs at half speed, its effects, regeneration and damage over time's ticks, while everyone else's runs as usual | `dao/Clock.h`, `dao/Timers.h`, `dao/Effects.h` |
| [`saves/`](saves/Saves.cpp) | A plugin's own data kept with the game's saves: a count of the saves made in a playthrough, written with each save and read back from the save being loaded, so loading an older save brings back its count and a new game starts from nothing | `dao/Saves.h` |
| [`atmosphere/`](atmosphere/Atmosphere.cpp) | A day and a night where the party stands, with no load: the area's own sky and sunlight blended to a night made on the spot and back, once, over two minutes | `dao/Atmosphere.h` |
| [`objectids/`](objectids/ObjectIds.cpp) | An object's id chosen by the plugin: the same dog made by the scripts' call, under an id ahead of the game's numbering, under one in use, under a free one behind, and after the numbering is moved, each id logged against the one expected. | [`resources/`](resources/Resources.cpp) | Every place the game finds its files in, in the order it looks, and where each file `where.txt` names comes from. | [`resume/`](resume/Resume.cpp) | Straight back into the game: at the main menu, the save written last is loaded with no menu touched. Also how a check in play gets into the world with nobody at the keyboard | `dao/Saves.h`, `dao/Frame.h`, `dao/ClientExoApp.h` |

To see one work: deploy it, play, and read its log. For `saves/`, save twice, load the first save, and save again: the log counts 1, 2, then back to 1 on the load and 2 on the next save. A new game logs that it counts from nothing. For `speed/`, start a fight: everything but the menus should move twice as fast until it ends. For `clock/`, get the controlled creature poisoned or burning in a fight: its ticks come half as often as anyone else's, and the log's time left on its effects runs down at half the rate; when the fight ends the log says how many timers were given back. For `commands/`, give the controlled creature orders and fight: each start and end is logged, failures for anyone. For `cooldown/`, use an ability from the quickbar: the log has the cooldown the game gave it, and the slot's sweep should then stand two thirds full and barely move. For `preview/`, move the cursor over the ground in explore or combat mode: a ring follows it, the log saying in reach (within 10 m of the controlled creature) or too far. For `dialogue/`, talk to someone with choices: the log has each line, the replies in their order, and those not offered. For `world/`, walk about and point at creatures, doors and chests: the log says whether the controlled creature can see each, the walk the pathfinder finds to it and the room it is in, and every two seconds what lies beneath the creature; every ten seconds it logs the walks to the six creatures nearest, so the log has them with no one at the mouse. For `damage/`, fight: its log gives each party member's hit and the half taken. For `party/`, switch who you control by the party bar and by key, equip and unequip in the inventory, and equip a two-handed weapon over a shield: each change is a line, the shield's coming off before the weapon's going on. For `camera/`, select another party member, close in and in the tactical view: the camera glides over, and close in comes round behind them. For `atmosphere/`, stand outdoors: over a minute the sky darkens to a purple night and the ground goes moonlit blue, the party's shadows fading, and over the next it all comes back, once; the log has the share of night every ten seconds and says when the area has its own look again.

Writing one is also a review of the API it uses. Where an example is awkward to write or has a trap in it, the library is changed rather than the example worked around: `saves/` is why `dao/Saves.h` has `OnGameLoaded` (which also tells a plugin of a new game, so no state leaks from one playthrough into the next) and `Read`/`Write` (so no plugin writes file boilerplate or leaves half a file in a save); `camera/` is why `dao/CameraMoves.h` has `Current()` (one call for the camera in the modes it moves in) and `OnTargetChanged` (selection as an event rather than a target polled every frame); `damage/` is why `CommandCall` has `SetInt`, `SetFloat` and `SetObject` (changing an argument before the command runs, which only an answer could be before); `speed/` is why `CClientExoApp::Mode` gives nothing, rather than a crash, before the game's modes exist, and `CurrentMode()` asks from anywhere; `world/` is why `CClientExoApp::CurrentExplore()` exists (explore mode in one call, rather than three null checks), and why `LineOfSight` answers a `Sight` that converts to bool and says where the view was cut, rather than an out parameter. `atmosphere/` is why the library reads a sky at all (the script commands only set one, a number at a time), why the sunlight has an `AreaOwnSunlight` and a `ResetSunlight` though the engine keeps no copy of it (the library keeps what its first write went over), why `dao/Framebuffer.h` reads an effect's state (the example's first version, the harness of DAOLib #62, ended a grade by turning the effect off, which left every area a third darker than a load does, since the game has it on with values no command gives), and why `dao::script::Table()`, the command table, became `CommandTable()`: beside it the name `dao::script::Table`, the data tables' enum, could not be said.

`src/plugins/example/` is older: one plugin that checks many parts of the library at once in play. What it shows moves here, one part at a time.
