# A material as the engine reads and chooses it

The material layer end to end: the three files a material is made of (`.mat`, `.mao`, `.sta`), the `.mat` grammar as the engine's expat builder parses it, the rule that picks one technique from a semantic's tree of logic blocks, effect passes, parameter sets, the semantics' lookup rules, the elements the builder leaks and so ignores, and the `.mao` reader with its nine parameter kinds. It is written to port from: every condition, constant and order has its address, and a step the readings did not read is said to be unread where it stands. The home of the material layer; what already had a home stays there and is linked, not copied: the `.sta` state machine, the 40 materials preloaded at start and the weak handles are `dev/FRAME_EFFECTS.md` ("Material states (.sta)" and the sections after it); the `lm.dds` placeholder `Default_Black` is `dev/SKY.md`; the case of a `.mao`'s element names is `dev/PARAGON_MAO_CASE.md`; what the readers in core hold is `src/dao/core/MaterialDefinition.h` and `MaterialObject.h`.

Sources and marks. Six reconciled readings by paragon-agent of the .mat parser end to end and the .mao reader (render-13, -17, -18, -19, -20, -21; each two independent readings reconciled; read 2026-11-01; DAOParagonEngine #351), and render-14, -15 and -16 for the states, shaders and the material object. Marks: **[C]** checked in the GOG exe (`extern\DAOAddressLibrary\tools\daoexe.py --disasm`) in writing this note, 2026-11-01; **[C by the reading]** what a reading says it checked in the exe, not repeated here; **two readings reconciled** where the two readers agreed, or one was settled against the other in the disassembly, and nothing more was checked; **[I]** inferred, not read; **unread** a step no reading looked at. Addresses are GOG's. Offsets are from the disassembly; Ghidra's structs for these classes sit 4 to 0x20 bytes low.

Where core stands. `MaterialDefinition.h` reads a `.mat` as the builder does (DAOLib #298): elements by the parent's kind with a misplaced one inert and its subtree, element and attribute names without case, `Name` or `ID`, a semantic's first `Logic` as its tree of blocks and a block's first `Technique`, each test's word built attribute by attribute, a pass's parameters as the set references and own parameters leave them, an `Effect` pass bare, and a parameter's `Min`, `Max`, kind, stage, count and defaults (`Parameter::Valid`, `Vector4Groups`, `MatrixValue` and the rest); `SelectTechnique` is the technique choice and the validity below (the shader models, the detail levels, the passes' and techniques' validity), and `SemanticNamed` and `DefaultSemantic` the semantic lookups (#296). Not in core: the files a pass names (a shader that does not load, the state block, an `Effect` that is not found: the caller's, and an invalid pass is not stepped over), an internal parameter's `Usage` (0x00509870, so one with usage 0 is still in the pass), `ArtParameter`'s and `InternalParameter`'s remaining attributes, and the `.mao` (#297).

## The files

(render-13, -14, -16, -17, read 2026-11-01; DAOParagonEngine #351; two readings reconciled)

- **`<name>.mat.xml`**, in `materials.erf`, is a material definition (`Graphics::Material`, vftable 0x00AF4210, built by `MaterialBuilderXML2` 0x0050D090/0x0050C7E0 for the file and `new 0x3C` at 0x004F8283 inside the loader 0x004F8150). The `.mat` name is the material's, matched without case (`MaterialManager::GetMaterial` 0x004F8370). A material is a named list of semantics, one of which is the default; each semantic holds a tree of logic blocks that picks one technique; a technique is a list of passes; a pass is a vertex shader name, a pixel shader name, a render-state block (a `.sta` name), parameters and the vertex streams it needs. Or a pass runs a frame-buffer effect instead (below).
- **`<name>.mao`** and **`<name>.mao.xml`**, a material object (`Graphics::MaterialObject`, 0x158 bytes, vftable 0x00AF41D0): the `.mat` it uses, which semantic, and the parameters it overrides. A model lists `.mao` names. `MaterialObjectManager::Load` (0x004F72D0) appends `.mao` when the name is shorter than 4 characters or does not end in `.mao` (`EqualsNoCase`, string 0xAF2B80), then asks the resource manager for **name + ".xml" first** (the string 0xAF2B74 joined at 0x004F742A..0x004F7438, `Resources::Find` at 0x004F7470, type at 0xAF046C), and only when that is absent for the plain name (0x004F7487..0x004F74A6) [C]. So a mod's `.mao.xml` wins over a `.mao` of the same name. (`dev/FRAME_EFFECTS.md` says the object manager "retries with `.xml` as the second name"; the order is the other way round, as here. That sentence is to be corrected there.) A name that cannot be loaded, or an object that is not valid, is replaced by `Default_Miss01.mao` (the static wstring 0x00C30918, built from the literal at 0x00AF2B98 by 0x00ACF000 [C by the reading]): by `GetOrLoad` 0x004F78E0 (retried unless the name already is the default, `EqualsNoCase`), by the instance bind 0x004F49B0 and by the terrain blueprint 0x005B2C01. A name is loaded again for every object by `MaterialObject::Load` 0x00502CD0 (the reload on a detail-level change; only caller `SetGraphicsDetailLevel` 0x00458FE0 through `ReloadAll` 0x004F6F60).
- **`<name>.sta.xml`**, in `states.erf`, a render-state block. A pass names one by its `State` attribute; `MaterialPass::LoadStateBlock` (0x005062F0) looks the name up (`MaterialStateManager::FindOrLoad` 0x004FC960) only when the pass has no state yet (+0x54 null, 0x00506314) and ignores the state's valid byte (read at 0x00506376, result unused at 0x0050637B). The file's vocabulary, the default state and the apply rule are in `dev/FRAME_EFFECTS.md`. A core reader of the format is DAOLib #295.

The material system's other files (shaders `.vsh/.psh` in `shaders.erf`, frame-buffer effects `.ffx.xml`) are only named here where a pass uses them.

## The .mat grammar as the engine parses it

(render-19, -20, -21, read 2026-11-01; DAOParagonEngine #351; two readings reconciled each, the points marked [C] checked in the exe)

The builder is expat-driven. Each XML element becomes a temp object on a stack (`MaterialBuilderXML2` +0x10, vector begin +0x14, end +0x18). **StartElement** (0x0050D090) makes the temp for the element's name, matched without case (`__wcsicmp` 0x008E687B), pushes it, then calls its `ReadAttributes` (slot 2, 0x0050D8D3) with the attribute array (name/value `wchar_t*` pairs ended by a null name); attribute names are also matched without case. **EndElement** (0x0050C7E0, slot 2 of vftable 0xAF4E28, reached through expat's end handler 0x005076E0) builds the top temp (its slot 1 `Build`, always first) and hands the product to its parent according to the pair of kinds, then pops. `Meta` elements are skipped at both ends (the byte +0x28 set at start, cleared at end 0x0050C827; no push, no pop). Character data is ignored (handler `Stub::NoOp_8` 0x00738C90). A second `Material` inside a file is not special-cased. Unknown attributes are ignored by every temp.

Element name to temp (StartElement's `wcsicmp` chain, 0x0050D090; each temp's constructor passes its kind bit to `MaterialBuilderTemp` 0x005095F0, read back by slot 3 `GetKind` 0x00A222A0):

|---|---|---|---|---|
| `Material` | MaterialTemp | 0x1 | 0x3C (0x0050D121) | 0x0050CFE9 (push); constructor 0x0050CFC0; only on an empty stack, `new 0x78 Material` (0x00503780) at 0x0050D17E |
| `Semantic` | MaterialSemanticTemp | 0x2 | 0x48 | 0x0050ACB8 (push); created only under a parent whose kind has 0x1 (0x0050D250..0x0050D259) |

| `Parameter` or `ArtParameter` | MaterialParamTemp | 0x20 | 0xD8 | 0x0050AABB (push); only under a parent whose kind has 0x1010 (a pass or a parameter set, 0x0050D859..0x0050D883) |
| `InternalParameter` | MaterialInternalParamTemp | 0x40 | 0x68 | 0x00509798 (push); 0x0050D54E, caller 0x0050D56E |

**StartElement's dispatch** (render-22, read 2026-11-01; DAOParagonEngine #351; addresses [C by the reading], two readings reconciled; `MaterialBuilderXML2::StartElement` 0x0050D090, slot 1, `ret 8`, reached from expat through `StartElementCallback` 0x008523F0). Fields: +4 result handle, +0x10 temp stack, +0x20 "build into the existing +4 material" byte (0 from the constructor 0x0050C6C8, never changed by the only caller 0x004F8150, so the in-place branch is unused), +0x28 in-`Meta`, +0x2C the parameter sets. By name, without case:

1. `Meta` (0x00AF4494): +0x28 = 1, return, nothing pushed (0x0050D0BA..0x0050D0E2).
2. `Material` (0x00AF4428): only when the stack is empty, otherwise return with nothing pushed (0x0050D0FB..0x0050D10D). Clear the sets (+0x2C, `DeleteAll` 0x0081EEB0, 0x0050D113). If +0x20 is set, a MaterialTemp around a copy of the +4 handle (0x0050D11D..0x0050D153); else `new 0x78 Material(1)` (0x00503780) in a handle, wrapped in a MaterialTemp (0x0050D17E..0x0050D1D2).
3. Every other element needs a non-empty stack (else return, nothing pushed) and tests the kind bits of the top temp (its slot 3, `[vt+0xC]`): the parent must **be** of the kind listed. Parents (the test and the `new`): Semantic 0x1 (0x0050D259, 0x0050D25D); Logic 0x2 or 0x4 (0x0050D314, 0x0050D321, 0x0050D329); LogicTest 0x4 (0x0050D39F, 0x0050D3A7); Technique 0x4 (0x0050D419, 0x0050D421); Pass 0x8 (0x0050D492, 0x0050D49A); Parameter and ArtParameter 0x10 or 0x1000 (0x0050D859, 0x0050D860); InternalParameter 0x10 or 0x1000 (0x0050D543, 0x0050D54E); EffectParameter 0x10 (0x0050D5BF, 0x0050D5C7); RequiredStreamData 0x10 (0x0050D644, 0x0050D64C); Stage 0x10 (0x0050D6BD, 0x0050D6C5); ParameterSet 0x1 (0x0050D73F, 0x0050D747); ParameterSetRef 0x10 (0x0050D7B8, 0x0050D7C0).
4. Anything else, or a wrong parent, makes a MaterialUnknownTemp (0x0050D7FB, 0x0050D89B, 0x0050D29A). Unknown has kind 0x100 and passes no test, so **everything under a misplaced or unknown element becomes Unknown too: the whole subtree is inert.** A Pass outside a Technique or a Parameter outside a pass or set is therefore never built (0x0050D494, 0x0050D85E); render-21 said it was built and dropped, which is corrected here.
5. The new temp is pushed (0x0049D170) and the top's slot 2 `ReadAttributes` is called with the attributes (0x0050D8B4..0x0050D8D7).
6. Quirk: `Stage`, `ParameterSet` and `ParameterSetRef` on an **empty** stack skip the push and jump to `ReadAttributes` on the "top" (0x0050D69C, 0x0050D71E, 0x0050D797 to 0x0050D8C4); the bounds-checked getter `Back` (0x0050B5A0) returns the static null cell 0x00C31258 for an empty vector (0x0050B5EF), so the call goes through a null object and would crash the game. No shipped file has a root-level element of these kinds; a reader skips them. A nested `Material` or other elements on an empty stack are not pushed either (0x0050D10D, 0x0050D223), but every end tag except `Meta`'s pops (0x0050CEE2), so such a tag would pop its parent; no shipped file does it. Children of a `Meta` are dispatched against whatever is on the stack.

A `Logic` nested in a `Logic` is allowed (the kind test is on bits), so the logic tree is recursive. After the parse, `MaterialBuilderXML2::TakeResult` (slot 4, 0x0050CF00) returns null if the done byte +0xC is 0; otherwise it calls `Material::Validate` (slot 12, 0x00503240) on the result (0x0050CF44..0x0050CF5B), moves it out and clears +0x4 and +0xC (0x0050CF5D..0x0050CF77). The result can be taken once, and **a material with no default semantic or no valid semantic draws nothing** (validity, below). The loader 0x004F8150 calls it right after the parse (0x004F829C).

What the shipped files use (render-22's scan with ghilana: 475 `.mat.xml`, 462 core and 13 Elgara plugin overrides, and 188 `.sta.xml`; enciphered add-ins not scanned): every root is `Material`; no `ArtParameter`, `Stage` or `Meta` element, no `ID` attribute and no pass `Effect` attribute anywhere (so effect passes and `Stage` ids are in the engine and unused by these files); no element on an empty stack; exactly one misplaced element: an `EffectParameter` directly under a `ParameterSet` in `distortionmaskdiffuse.mat.xml` (its comment says "Force load the distortion framebuffer effect"), which the exe makes Unknown, so it does nothing.

The `Parameter` `Type` strings `CreateArt` (0x005093D0) understands: `Texture` (new 0x34, MaterialArtTexture 0x0050F320), `Float` (new 0x1C, 0x0050F270), `Vector4f` and `Vector4fArray` (new 0x28, MaterialArtVector4f 0x0050F4E0, its +0x10 = Size), `Matrix4x4f` (new 0x60, 0x0050F290); any other type gives null, and a null parameter is dropped with its temp (0x0050CAA9). It then sets, in this order, the sampler name (slot 4), the stage (slot 3), the name id (0x0050F070: `MaterialParameterNames` id of the name, stored at +8), the default (slot 5), min (slot 6), max (slot 7) and finishes (slot 8) (0x0050950F..0x00509569). For a texture, slot 3 stores the stage, slot 5 takes the default texture's id only when none is set, and slots 6 and 7 do nothing (`NoOp_4`) [C by the reading]. `InternalParameter`'s `Type` strings and `CreateParam` (0x0050B360) are unread here.

**The tree EndElement builds** (0x0050C7E0; the child's kind is tested bit by bit in this order, with the parent's kind at stack[size-2] fetched by the bounds-checked `At` 0x0050AD70, which yields the static null cell 0x00C31258 out of range). Hierarchy: Semantic under Material; Logic under Semantic or Logic; LogicTest and Technique under Logic; Pass under Technique; Parameter, InternalParameter, EffectParameter, RequiredStreamData, EffectStage and ParameterSetRef under Pass; Parameter and InternalParameter also under ParameterSet; ParameterSet under Material. For each kind the child's `Build` runs first, then:

1. 0x1 `Material` (0x0050C880): when the builder's +0x20 is 0, the child's slot 6 (`GetMaterial` 0x0050D070) is assigned into the builder's safe pointer +4 (0x004F4710); the child is deleted; the ready byte +0xC = 1 (0x0050C8CD). The loader takes the material through slot 4 (`TakeMaterial` 0x0050CF00). Who sets +0x20 is unread.
2. 0x2 `Semantic` (0x0050C8DD): parent kind & 1: the parent's slot 5 (`MaterialTemp::AddSemantic` 0x0050C170, pushes a non-null child) takes it (the temp is then owned by the parent); else the child is deleted.
3. 0x4 `Logic` (0x0050C92F): parent & 2: the parent's slot 9 (`MaterialSemanticTemp::SetLogic` 0x00509620, stores at +0x40 only if empty: a semantic's first Logic child is its root, a second is neither kept nor freed); else parent & 4: the parent's slot 8 (`MaterialLogicTemp::AddChild` 0x0050C3D0, push into +0x24, a nested block); else deleted.
4. 0x200 `LogicTest` (0x0050C995): parent & 4: the parent's slot 9 (`AddTestFlags` 0x00509590, `parent+0x34 |= child+8`, the child's own flags from its slot 4); the child is always deleted (0x0050C9E3).
5. 0x8 `Technique` (0x0050C9F7): parent & 4: the parent's slot 7 (`MaterialLogicTemp::SetTechnique` 0x005095E0, `+0x3C = child` only if +0x3C is 0): the first technique of a Logic wins, a second is neither kept nor freed; else deleted.
6. 0x10 `Pass` (0x0050CA39): parent & 8: the parent's slot 7 (`MaterialTechniqueTemp::AddPass` 0x0050C3D0, push into +0x24); else deleted. Passes are added in file order, which is the draw order of a multi-pass technique [I].
7. 0x20 `Parameter` (0x0050CA6C): parent & 0x10 (a pass): when the child's slot 4 (`GetParam` 0x0050AC40, +0xD4, set by `Build` 0x00509580 from `CreateArt`) is non-null, parent slot 13 (`AddParam` 0x0050BD20) with (parameter, 0); the child is deleted either way (0x0050CA9A..0x0050CAD6). Parent & 0x1000 (a parameter set): the unbuilt child temp itself is pushed into the set's +0x24 (0x0050C3D0 at 0x0050CAF4) for later references.
8. 0x40 `InternalParameter` (0x0050CB03): as 0x20, with the parent's slot 14 (`AddInternalParam` 0x0050BE00); for a set, `MaterialParamSetTemp::AddInternalParam` 0x0050C3E0 into the set's +0x34 (0x0050CB31..0x0050CB8B).
9. 0x800 `EffectParameter` (0x0050CB9A): the parent's kind is fetched (0x0050CBB7..0x0050CBC5) and `test al,0x10; je 0x0050CEC9` at 0x0050CBC9 [C]; see "Ignored elements" for the leak. With a pass parent: the child's slot 4 result, if non-null, to the parent's slot 14 (`AddInternalParam`, flag 0); then the child's +0xBC (the `MaterialArtEffectTexture`, if non-null) to the parent's slot 13 (`AddParam`, flag 0) (0x0050CBCF..0x0050CC08); the child is deleted. So one effect parameter can give a pass both an internal parameter (a float or Vector4 read from the effect) and a plain texture parameter.
10. 0x80 `RequiredStreamData` (0x0050CC16): parent & 0x10: the parent's slot 15 (`AddRequiredStream` 0x0050BD10, push into the vector at +0xB4) with the child's slot 4 (its name at +0x8); deleted.
11. 0x400 `EffectStage` (0x0050CC6F): parent & 0x10: `AddEffectStage` 0x0050BEE0 (push into the vector at +0xC4) with the child's id (+8); deleted.
12. 0x1000 `ParameterSet` (0x0050CCB9): see "Ignored elements" for the leak; parent & 1: the set is pushed into the builder's own +0x2C (0x0050CCE4..0x0050CCF8) and not deleted (owned by the builder, freed by `DeleteAll` 0x0050C77E at its destruction).
13. 0x2000 `ParameterSetRef` (0x0050CD07): see "Parameter sets".
14. Anything else (kind 0x100): built (the Unknown's `Build` is a no-op) and deleted (0x0050CEA2..0x0050CEC7).
Every path but `Meta` ends by popping the stack (`resize(size-1)` 0x004A62E0 at 0x0050CEE2). A misplaced element never reaches this point as its kind (StartElement made it Unknown, above); it is dropped and nothing is reported.

**What each temp's Build makes** (all [C by the reading], two readings reconciled):

- `MaterialTemp::Build` (0x0050B2E0): Material slot 10 (`SetName`, `+0x1C = name`), then for each semantic temp in +8 its slot 6 (the built `MaterialSemantic`, +0x44) to the Material's slot 9 (`AddSemantic`, "Semantics", below).
- `MaterialSemanticTemp::Build` (0x00509630): `new 0x40` MaterialSemantic (0x004F6BC0) into +0x44; `SetName(+8)` (0x004F6E80: the name, and its interned id `NameToId` 0x004F6DA0 at +0x3C); `SetCategories(+0x24)` (0x004F6D60, the RenderClass, below); if the Logic child (+0x40) exists: `MaterialLogicBlock::Validate(tree)` (0x00507330, the tree being the child's slot 5 result), `SetTechniqueTree(tree)` (0x004F6AA0: `+0x20 = tree` only when +0x20 is 0); then `SelectTechnique` (0x004F6AB0) and `Validate` (0x004F6CD0). A semantic with no Logic child never gets a tree; what `SelectTechnique` does with a null tree is unread, and `Validate` marks it invalid (no tree).
- `MaterialLogicTemp::Build` (0x0050AE10): `new 0x20` MaterialLogicBlock (0x00507650) into +0x38; block +0x1C = the temp's +0x34 (the OR of its LogicTests' flags; `SetDword_0x1C` 0x0081CDD0); each child temp's built block (slot 5) pushed into block +4 by `AddChild` (0x005076C0, non-null only); if the technique temp (+0x3C) exists: its built technique (slot 5) given to `MaterialLogicBlock::SetTechnique` (0x00507260, `+0x14 = t` only if empty) and then `MaterialTechnique::Validate` (0x00506F00) is run on it. Nested Logic children are built before their parent because EndElement closes them first.
- `MaterialTechniqueTemp::Build` (0x0050BC10): `new 0x40` MaterialTechnique (0x00507080) into +0x34, its name copied (0x00503980); each pass temp's built pass (slot 8, +0xE8) to `AddPass` (0x00507200), the temp deleted; the temp's list cleared; `MaterialTechnique::Validate` (0x00506F00).
- `MaterialPassTemp::Build` (0x0050B2C0): `cmp [ecx+0x8C],0` (the Effect string's length): empty, `BuildPass` (0x0050AF10); else `BuildEffectPass` (0x0050B0C0) ("Effect passes").
- `BuildPass` (0x0050AF10), in order: `new 0x114` MaterialPass (0x00505F20) into +0xE8; vertex shader name `pass+4 = temp+0x24` (0x00503980); pixel shader name `pass+0x20 = temp+0x40` (0x00503990); `LoadStateBlock(temp+0x5C)` (0x005062F0); `SetRequiredStreams(temp+0xB4)` (0x00503D80, below); each parameter of temp +0x94 to `AddParameter` (0x00504D80, push into pass +0x68, non-null only); each internal parameter of temp +0xA4 whose +0x20 (its Usage, set by `CreateParam`) is non-zero to `AddBinding` (0x00504DA0), which files it in pass +0x88 when its +0x20 is below 0x20, else in pass +0x78; an internal parameter with usage 0 is left out of the pass (and leaked); finally the pass's slot 4 (`MaterialPass::Validate` 0x005040F0).
- `MaterialInternalParamTemp::Build` (0x0050B4C0): `+0x60 = CreateParam()` (0x0050B360, unread).
- `MaterialEffectParamTemp::Build` (0x00509FB0): see "Effect parameters".

**Required streams** (`SetRequiredStreams` 0x00503D80, from the pass builder; names matched without case, strings at 0x00AF4334..0x00AF4270): the pass's `+0xE0` mask gets bit `1 << usage` (0x00867EF0) for POSITION 0, BLENDWEIGHT 1, BLENDINDICES 2, NORMAL 3, PSIZE 4, TANGENT 6, BINORMAL 7, TESSFACTOR 8, POSITIONT 9, FOG 11, DEPTH 12, SAMPLE 13 (the D3DDECLUSAGE numbers). A name whose first 5 characters are `COLOR` sets usage 10 and bit n of the byte at +0xE8, n being the rest of the name as an integer (0x00867F20, empty reads 0) (0x00503FCB..0x00504036). ## The technique choice

(render-13, -17, -18, -19, -21, read 2026-11-01; DAOParagonEngine #351; the test, the walk and the mask bits [C] in this note; the rest two readings reconciled)

**Which technique a semantic draws with is chosen by walking its tree of logic blocks; the first block whose tests pass supplies it.** Each `Logic` block is a `MaterialLogicBlock` (0x20 bytes, vftable 0x00AF43AC): +4 the vector of child blocks (begin +8, end +0xC), +0x14 its technique (owned), +0x18 a valid byte (1 at construction), +0x1C its test flags. A block is a leaf with one technique or an inner node of children, never both (Validate below).

The test flags (a block's +0x1C is the OR of all its `LogicTest` children's words, `AddTestFlags` 0x00509590). One `LogicTest`'s own word (temp +8) is built by its two attributes:

1. `ShaderModel` (`SetShaderModel` 0x005095A0, the value parsed by `wcstoul` 0x004C0990) [C]: `3`: `word |= 1` (0x005095B1). `2`: `word |= 2` (0x005095BE), then if any of `word & 0x1C` is set, `word &= 0xFFFFFFE3` (0x005095C4..0x005095CB), clearing the detail bits already there. Any other value: nothing.
2. `Detail` (`SetDetail` 0x0050ADA0, compared by `_wcsicmp`) [C]: if `word & 2` is set (an SM2 test) it does nothing (0x0050ADB6). Otherwise `HIGH` (string 0x00AF4CEC): `word |= 4`; `MEDIUM` (0x00AF4CDC): `word |= 8`; `LOW` (0x00AF4CD4): `word |= 0x10`; anything else nothing.

So attribute order within one `LogicTest` matters: `ShaderModel="2"` after `Detail` clears the detail bits, `Detail` after `ShaderModel="2"` is dropped. Whether any file depends on the order is unchecked. The OR of several LogicTests in one Logic is not re-cleared: a block with a `ShaderModel=2` test and a separate `Detail=HIGH` test has word 2|4 = 6, and both are tested below.

`Test(block, device)` (`MaterialLogicBlock::TestsPass` 0x00507280) [C, disassembled in full 2026-11-01]. `level` is the global detail level at 0x00BF22C8 (0 to 3; 3 is the highest, "HIGH"). `caps` is `device->slot42` (the vtable word at +0xA8, 0x0050728B) and `caps->slot2(n)` (the vtable word at +8) asks whether shader model n is supported:

```

cl = (level == 0)                                   ; 0x00507295, 0x005072A1
w  = block.flags (+0x1C)                            ; 0x0050729E
if (w & 3):                                         ; 0x005072A4
    if (w & 2):                                     ; SM2 test      0x005072AC
        if (level != 0): bl = caps(2) & 1           ; 0x005072B6..0x005072C7  (at level 0 the SM2 test passes with no caps check)
    if (w & 1):                                     ; SM3 test      0x005072CA
        if (level == 0): return false               ; 0x005072D0..0x005072DA
        bl = bl & caps(3)                           ; 0x005072DD..0x005072E8  (caps(3) taken whole, not masked to bit 0)
    if (bl == 0): return false                      ; 0x005072EA
if (w & 0x1C):                                      ; any detail bit  0x005072EE
    al = 0
    switch (level):                                 ; 0x005072F6..0x00507321
        3: al |= (w >> 2) & 1                       ; HIGH   (falls through to 2)
        2: al |= (w >> 3) & 1                       ; MEDIUM (falls through to 1)
        1: al |= (w >> 4) & 1                       ; LOW
        else: al = 0                                ; level 0 (and above 3) passes no detail test

return bl
```

So HIGH admits level {3}, MEDIUM {2, 3}, LOW {1, 2, 3}; level 0 admits none of the three. SM3 needs a level above 0. A block with no flags passes. `device->slot42` (vtable +0xA8) of `D3DGraphicsDriver` is `mov eax,[ecx+0xFC]` (0x0081B2C0), and the only class with a slot 2 that takes a number and answers a byte is `D3DGraphicsCapabilitiesDriver` (vftable 0x00B2DEF4; the other candidate, `ExternalDeviceCaps` 0x00B2DB38, has a slot 2 that returns an address): **slot 2 (0x0086E090) is true when the vertex shader's major version (+0xED) and the pixel shader's (+0xF5) both equal n, exactly**; slot 3 (0x0086E0C0) is "at least n" and is not what the test calls [C, 2026-11-01; that +0xFC is that object was not traced to its store]. So `caps(2)` is false on a shader model 3 device: a `ShaderModel="2"` block is taken by a shader model 2 device (or at level 0, which asks nothing), and a shader model 3 device takes the shader model 3 blocks. Core's `SelectTechnique` takes `shaderModel3` and treats a device without it as having 2 (a device with neither, or vertex and pixel at different versions, passes no shader model test above level 0; not modelled).

`SelectTechnique(block, device)` (`MaterialLogicBlock::SelectTechnique` 0x005073C0) [C, disassembled 2026-11-01]; `device` is the graphics driver manager's slot 7 (0x00867E30, static 0x00C3A020), taken by the semantic's `SelectTechnique` 0x004F6AB0 (0x004F6AB3..0x004F6ACA):

The block's own valid byte is not tested on the way down; only the semantic's `Validate` reads the root's byte (below). The semantic stores the result at +0x24 (0x004F6ACA). **Validity, which can make a semantic draw nothing** [C by the reading, two readings reconciled; the block rule disassembled in part]:

1. `MaterialLogicBlock::Validate` (0x00507330): if the block has a technique (+0x14): `valid = 0` when it also has children (0x0050733B..0x0050734C); and `valid = 0` when the technique's own valid byte (+0x20, `GetByte_0x20` 0x00506E30) is clear (0x00507350..0x00507357). **When the choice is made.** At the `.mat`'s build, in `MaterialSemanticTemp::Build` (0x00509630), against the detail level at that moment. Again, for every material, when the graphics detail level changes: `SetGraphicsDetailLevel` (0x00458EB0) calls `MaterialManager::RebindMaterials` (0x004F7BF0 at 0x00458FD4), which takes the manager's lock and calls `Material::SelectTechniques` (0x005033B0 at 0x004F7BF0's loop): for each semantic `SelectTechnique` (0x004F6AB0, called at 0x005033F1), then a tail jump to `Material::RebindPasses` (0x005032D0), which for each semantic with a chosen technique calls each pass's slot 5 (`Rebind` 0x00505ED0 for a normal pass: caches the shader handles at +0x4C/+0x50 and re-resolves the parameters; a no-op 0x005BDCF0 for an effect pass). **For the port at the highest setting**: `level = 3`, both capabilities present: a block passes when its flags have no `ShaderModel 3` blocked (SM3 passes at level 3), no SM2 requirement failing (SM2 passes with the capability), and a detail word of 0 or with any of HIGH, MEDIUM, LOW set (any of the three admits level 3). The first such block that has a technique with a valid pass list wins, in file order.

`EqualsNoCase` (0x004C0A50) compares the lengths first (`cmp edx,[eax+0x14]; je`) and then the characters through 0x004C0350 with the length (case-insensitive) [C]. **So of two exactly equal names the first counts (AddSemantic drops the second), and of two differing only in case the later is found** (both are kept by AddSemantic, FindSemantic searches from the last). `Material::FindSemanticById` (0x005031C0, not virtual) is the same reverse walk comparing each semantic's id (+0x3C via `GetId` 0x004F6A90); sole caller 0x004F27ED. ## Validity and the object's use of it

(read 2026-11-07 for DAOParagonEngine's render port; **[C]** in the GOG exe; **[I]** inferred. Core's structs are named so the rules can be written over them: `dao::core::mat::Definition`, `Semantic`, `Block`, `Technique`, `Pass`, `Parameter`, and `dao::core::mao::MaterialObject`.)

**A semantic's validity** is stored once, at the `.mat`'s build, in `MaterialSemanticTemp::Build` (0x00509630), in this order [C]: `SetName` (0x004F6E80, 0x0050968B), `SetCategories` (0x00509697), `MaterialLogicBlock::Validate` over the whole tree (0x00507330 at 0x005096AE; the structural test above, every block, whichever block would be chosen), the tree stored (0x004F6AA0), `SelectTechnique` (0x004F6AB0 at 0x005096BF, against the detail level and the device at that moment), then `MaterialSemantic::Validate` (0x004F6CD0 at 0x005096C7). The last is called from nowhere else: nothing recomputes the byte at +0x38 when the detail level changes (`SelectTechniques` 0x005033B0 re-chooses +0x24 and no more). It is valid when the name is not empty (0x004F6CD6; `Semantic.name`), the tree exists and its root byte +0x18 is set (0x004F6CDE; `Semantic.logic`, and every `Block` and `Technique` below it passing the structural rules), and a technique was chosen (0x004F6CF1; `SelectTechnique` in core is not null).

**The walk and the shader load, which corrects a line above and core's header.** `MaterialLogicBlock::SelectTechnique` (0x005073C0) clears no byte when a block's tests fail. A leaf calls `MaterialTechnique::ValidatePasses` (0x00506E40): 1 at once when the technique's loaded byte +0x21 is set; otherwise each pass's slot 2, `Load` (0x00506520: `LoadVertexShader` 0x00506110 and `LoadPixelShader` 0x00506200 must both succeed, then `ResolveParameters`), the first false giving 0, all true setting +0x21. A false clears the leaf's own byte (0x005073E2) and returns null, **and the parent goes on to its next child** (0x00507437, `test eax,eax; jne` returns only on a hit). A block clears its own byte only when every child failed (0x00507442). So a shader the pass names that will not load (its name empty at 0x00506147, or the resource lookup 0x004FE7F0 and the test 0x0045F1C0 failing at 0x0050619B) makes the semantic invalid only when no other block supplies a technique; the sentence "treats the technique as invalid and does not go on to the next block" in `MaterialDefinition.h` is wrong for that case. `ValidatePasses` never writes the technique's byte +0x20. A pass whose vertex shader handle (+0x3C) is already set returns false from `Load` (0x00506137..0x00506145), so a retry after a partial load fails again [I]. Core cannot decide this step: it does not know whether `Pass.vertexShader` and `Pass.pixelShader` exist in the install and compile on the device, nor whether `Pass.state` is a valid state block; a caller supplies that.

**A material's validity** is stored once, at the end of the parse. `MaterialBuilderXML2::TakeResult` (0x0050CF00) calls `Material::Validate` (0x00503240) and moves the material out whatever it returns, so an invalid material is still returned [C]. The byte at +0x38 is cleared when there are no semantics (0x00503255) or no default semantic (0x0050325F; `Definition::DefaultSemantic()` is null only when there are no semantics), and otherwise is set to **whether any semantic's stored byte is set**, walking from the last (0x005032A8..0x005032BD; `GetValid` 0x004F6A70 reads +0x38 and `MaterialSemantic::Validate` is not called again). The default semantic need not be the valid one.

**An object's validity** (object +0x10) is set by `ApplyMaterialDefaults` (0x00502BB0), called at the end of the parse by `TakeMaterialObject` (0x00507700) [C]. It is cleared when the object has no material or the material's byte is clear (0x00502BB5..0x00502BD6; Material slot 7 is 0x004F6A70). Otherwise, for each semantic of the material from the last, a semantic with no chosen technique (+0x24 null) is skipped (0x00502C3A), and for each pass of the chosen technique from the last, `ApplyParamDefaults` is called on the pass's parameters (0x00502C84); a false clears the object's byte (0x00502CA6) and leaves the rest of that semantic's passes. The object's own semantic, its `DefaultSemantic`, is not tested.

**The Default_Miss01.mao fallback** is made by the instance, not the object: `MaterialObjectInstance` binds its object at 0x004F49B0 and, when `object+0x10` is clear (0x004FE920, 0x004F49EC), takes `GetOrLoad(GetDefaultMaterialName())` (0x004F4A02) instead; either way `instance+0xC` is the bound object's default semantic (`+0x74`, 0x0042F940, 0x004F4A46). In core's terms the fallback happens exactly when the `.mat` has no valid semantic at all (or none: no `Material` element or a `.mat` that will not parse, which `GetMaterial` has already replaced by the default material), or when `ApplyParamDefaults` failed for a chosen pass. It does not depend on the object's own semantic. **A semantic other than the object's own** changes two things: it keeps the material valid, so a `.mao` whose own semantic is invalid does not fall back while another semantic of its `.mat` is valid; and the defaults of its chosen technique's passes are filled into the object's tables (below). An invalid other semantic does nothing. The instance's semantic is the `.mao`'s `DefaultSemantic` when `Material::FindSemantic` finds it (case-insensitive, last to first), else the definition's default, valid or not. `MaterialObjectInstance::Render` (0x004F5840) returns false at once for a null semantic (0x004F58FD) and then calls `GetTechnique` (0x004F6A80, `[+0x24]`) on the semantic and uses the result with no null test (0x004F5903, and the same at 0x004F5431), so an instance whose semantic is invalid is not drawn by a test those two sites make; the gate that keeps it from them was not found [I]. The render port's finding, that vanilla leaves it undrawn, is consistent with that and not explained by it.

**ApplyParamDefaults and the Default string** (0x005028C0; the fill table is under "What an unset parameter holds"). The argument is a pass's parameter container (begin +4, end +8, the art parameters; `Pass.parameters`), visited from the last parameter to the first, so the walk above is: semantics last to first, passes last to first, parameters last to first. The object has one table per kind keyed by the interned name, shared by every pass of every semantic, and a parameter is filled only if its table lacks the name (the `Has*Parameter` tests, which count a `.mao` array of no vectors as present). **The first visit of a name wins**: the `.mao`'s own value, else the default of the last semantic's last pass's last parameter of that name. A later pass with another Size or Default for it is not applied. Only the chosen technique's passes are visited, so a parameter that only an unchosen technique's pass has gets no default. Types 4 and 8 are skipped, and an effect pass's container was not read [I].

**`SetDefault` is called for every parameter** by `CreateArt` (0x0050953D), with the `Default` attribute or the empty string, which corrects the "definition has none" columns of "What an unset parameter holds" for a parsed `.mat` [C]. The "has a value" byte (+4) is set by `SetDefault` for a Float (0x0050F180, whose text is read by the leading-float parse 0x004C09D0, so no Default gives 0.0 [I: the CRT's result on no digits]), for a Texture (0x0050F0D0, the default name being the interned text, so none gives the name empty [I: what a texture named so binds]), and for a Vector4f or Vector4fArray (0x0050F540, at 0x0050F570 before the text is read). It is left clear only for a Matrix4x4f with an empty Default (0x0050F6AC), which is why the identity branch is the only one of the "none" columns that a `.mat` can reach. The array's "not set, returns false" branch (0x00502B49) needs a clear byte, so it is unreachable for a parsed `.mat`: an array with no Default is a Size-zero array and the object stays valid [I: for a hand-built art parameter]. The Default is read as any number of groups of four floats (0x0050F5C6..0x0050F632); the Size-cut case (0x00502AE7) resizes the definition's own default vector in place, which changes nothing since the Size is fixed. Core's helpers follow this: `Parameter::Vector4ArrayValue()` gives the first Size groups when the Default has at least Size, and Size zero vectors, not a partial fill, when it has fewer; `Vector4Value()` gives the group only when the Default has exactly one (two or more give zero); `MatrixValue()` gives the identity only for an empty Default; `FloatValue()` gives 0 with none; and an absent `defaultValue` and an empty one are the same to the engine.

## Ignored elements

(render-21, read 2026-11-01; DAOParagonEngine #351; both points [C] in this note, two readings reconciled and settled in the disassembly)

Two elements out of place are not attached and not deleted, so they are leaked, which means ignored:

- **A `ParameterSet` whose parent is not the `Material`**: after `test al,1` on the parent's kind, `je 0x0050CEC9` at 0x0050CCE6 [C] jumps to the stack pop at 0x0050CEC9, skipping both the builder's push (0x0050CCE4..0x0050CCF8) and the delete at 0x0050CEBF.
- **An `EffectParameter` whose parent is not a `Pass`**: after `test al,0x10` on the parent's kind, `je 0x0050CEC9` at 0x0050CBC9 [C] likewise skips the delete. With a pass parent the temp is deleted (0x0050CC0A `jmp 0x0050CEBF`). One reading said the temp was deleted in the wrong-parent case; it is not.

Other drops: a `Pass` outside a `Technique`, a `Technique` or `LogicTest` outside a `Logic`, a `Logic` outside a `Semantic` or `Logic`, a `Semantic` outside the `Material`, a `Parameter`, `InternalParameter` or `RequiredStreamData` outside a pass (a `Parameter` or `InternalParameter` also fits a set) are made Unknown by StartElement (0x0050D090), with their whole subtree, and never built. The two leaks above are therefore reached only when the wrong parent is itself a valid kind: an `EffectParameter` under a set (the one in `distortionmaskdiffuse.mat.xml`), a set under a non-Material. An unreferenced set's internal parameter temps leak (`~MaterialParamSetTemp` 0x0050C310 does not delete them). An internal parameter with usage 0 is left out of its pass. A second technique in a `Logic`, a second Logic child of a `Semantic` and a duplicate set name are not used (the first wins).

## The .mao and its nine kinds

(render-13, -16, -19, read 2026-11-01; DAOParagonEngine #351; two readings reconciled; the case-insensitivity also in `dev/PARAGON_MAO_CASE.md`)

`MaterialObjectBuilderXML2` (0xF0 bytes, vftable 0x00AF44A4; constructors 0x00507FE0 with a given target object and 0x00508110 with a device; slot 1 `StartElement` 0x00507E00, slot 2 `EndElement` 0x005077F0, slot 3 character data `NoOp_8` 0x00738C90, slot 4 `TakeMaterialObject` 0x00507700, slot 5 `ReadAttributes` 0x00508220). Every element name is matched without case (`_wcsicmp`, `EqualsNoCase`). `Meta` sets/clears +0xEC and is not pushed (0x00507E2B..0x00507E55; 0x0050781D..0x0050782F). **StartElement** for `MaterialObject`: with +0x27 = 0 (an object made by the loader, not given): if +4 is already set, return without reading the attributes (so a second `<MaterialObject>` in a file is ignored with its attributes); else `new 0x158 MaterialObject(device(+0x1C), 1)` (0x00502220) into +4 (0x00507EA4..0x00507EDA). **ReadAttributes** (0x00508220), per name/value pair, the element being the top of the stack; stops at once if +4 is null (0x0050826E):

- `Name` (0xAEDA08) or `ID` (0xB2BE58): on `MaterialObject` the object's name (+0x1C, 0x0057F630); on Texture, Vector4f, Vector4fArray, Matrix4x4f, Float, Material, Override, SoundType or DefaultSemantic: builder +0x2C = value, +0x20 = 1 (0x00508890..0x00508A55, 0x00508B9B..0x00508BD5).

- `Value` (0xAF44BC): `Vector4fArray`: a wide string stream over the value (0x004D2A20, 0x00454F20), the vector at +0xC0 cleared (0x00507F00 with 0), then until end of stream (0x004D29D0): a Vector4 of four zeros (0x004D4DD0) read with four `>> float` (0x00454300), pushed (0x00507D70); +0x25 = 1 (0x0050845E..0x00508512). - Other attributes are ignored.

4. `Matrix4x4f` (0xAF443C): needs +0x20, +0x26: `SetMatrixParameter(name, +0x80)` (0x00501050) (0x005079CB..0x005079D9).

## Parameters of a definition

(render-23 and render-24, read 2026-11-01; DAOParagonEngine #351; two readings reconciled each, the addresses [C by the reading]; render-24's corrections to render-23 are applied here)

The parameter factory is `MaterialParamTemp::CreateArt` (0x005093D0, `__thiscall`, returns the `MaterialArtParameter*`, plain `ret` at 0x0050957E; called by `Build` 0x00509583 and by the set loop 0x0050BFB0). A `MaterialArtParameter` is: +0 vftable (0x00AF4FD8), +4 byte "has a value" (0, set by `SetDefault`; read by 0x004ECF60), +8 the dword name id in `MaterialParameterNames` (0; set by `SetName` 0x0050F070 at 0x0050F084), +0xC byte valid (1). Names are interned process-wide (ids from the counter 0x00C31170 from 0, under the lock 0x00C31174; an unknown id's name is the shared empty wstring 0x00C31194).

1. The type string (`Type`, temp +8) is compared with `EqualsNoCase`: `Texture`: `new 0x34` MaterialArtTexture (0x0050F320). `Float`: `new 0x1C` MaterialArtFloat (0x0050F270). `Vector4f` or `Vector4fArray`: `new 0x28` MaterialArtVector4f (0x0050F4E0), and temp +0x5C (Size) written straight to its +0x10 (0x005094FB..0x005094FE). `Matrix4x4f`: `new 0x60` MaterialArtMatrix4x4f (0x0050F290). Any other type: null, and the parameter is dropped (0x005094C2). (`MaterialArtEffectTexture`, type 8, is made by `EffectParameter`, above.)
2. Then on the new parameter, in this order (0x0050950F..0x00509569), through vftable slots: 4 `SetSamplerName` with temp +0x9C; 3 `SetStage` (word) with temp +0x98; `SetName` (0x0050F070, not virtual) with temp +0x24 (0x00509536); 5 `SetDefault` with temp +0x40 (0x0050953D); 6 `SetMin` with temp +0x60; 7 `SetMax` with temp +0x7C; 8 `Validate`. A class overrides only the slots it uses. The vftable: 0 scalar deleting destructor, 1 `GetMemoryFootprint`, 2 `GetType`, then the slots above.
3. `GetType` (slot 2): Texture 0 (`Stub::ReturnZero` 0x004137B0); Float 1 (0x0079B310); Vector4f 2 and Vector4fArray 3, as `2 + (count(+0x10) > 1)` (0x0050F0B0); Matrix4x4f 5 (0x0046E640); EffectTexture 8 [I]. **Float** (constructor 0x0050F270): value +0x10 = 1.0, min +0x14 = 0.0, max +0x18 = 1.0 (0x0050F279, 0x0050F286, 0x0050F289). **That 1.0 is only what the range check sees**: the material gets 0.0 when the definition has no Default (below). `SetDefault` (0x0050F180) `value = StringToFloat(text)` (0x004C09D0) and +4 = 1; `SetMin` (0x0050F1A0) +0x14; `SetMax` (0x0050F1C0) +0x18, all with the script string-to-float (leading float). `Validate` (0x0050F2E0, slot 8): the base check (0x0050F2A0) stored to +0xC, then invalid if `value < min` (0x0050F2E8..0x0050F2F8) or `max < value` (0x0050F2FA..0x0050F307); the compare is an unordered x87 compare, so **NaN is invalid**. **Correction (2026-11-01, DAOLib #298): the range is not [0, 1] for a Float made from a `.mat`.** `CreateArt` always calls `SetDefault`, `SetMin` and `SetMax` (0x00509546, 0x00509553, 0x0050955D) with the temp's strings, whose constructor sets Min "-10000" and Max "10000" (0x0050AB32, 0x0050AB53; strings 0x00AF4C98, 0x00AF4C8C), so the constructor's 0 and 1 are overwritten and a Float with no `Min` and `Max` lies in [-10000, 10000]. `SetDefault` is also called with the empty text when there is no `Default`, which reads as 0 and sets the "has a value" byte, so a Float is valid with no `Default` (0 is in range). No shipped Float is out of range (the 843 are all in [-10000, 10000]; `weapontrail`'s `0.f` reads as 0). The base check (0x0050F2A0): the name id's name (`GetName` 0x00506870) of length 0 clears +0xC (0x0050F2B3..0x0050F2B9); a parameter with no name is invalid. The valid byte is sticky. Who acts on an invalid parameter is **unread**.

**Vector4f and Vector4fArray** (`SetDefault` 0x0050F540): +4 = 1 unconditionally (0x0050F570); the array is cleared (0x00507F00 with 0, 0x0050F58B); if the text is non-empty (0x0050F597): a wide `istringstream` over it (0x004D2A20, text set by 0x0050F440, which also clears the state), then while not at end (`0x004D29D0`: eofbit set, or `peek` (0x004D29C0) equal to WEOF; taken once before the loop, 0x0050F5BD, and after each push, 0x0050F62B): a Vector4 of four zeros (0x004D4DD0), four `>> float` into x, y, z, w (0x00454300), pushed (0x00507D70) (0x0050F5C6..0x0050F632). So a Default is any number of groups of four whitespace-separated floats; a short last group is pushed with the missing components 0; the end test does not skip whitespace, so **trailing whitespace after the last number adds one more all-zero element** [C structure; I that a failed `>>` leaves the zeros]; a non-number sets failbit, peek then gives WEOF and the loop ends [I]. The count `Size` (default 1) is stored at +0x10. An empty Default leaves the array empty with the mark set.

**Matrix4x4f** (`SetDefault` 0x0050F670): if the text is non-empty (0x0050F6AC): a wide `istringstream` and sixteen `>> float` into +0x10, +0x14 ... +0x4C **in file order** (0x0050F6D9..0x0050F7A4), then +4 = 1 (0x0050F7A9). An **empty Default leaves the matrix unset** (the constructor does not initialise the sixteen floats) and +4 = 0; the material then gets the identity (below).

**Texture** (constructor 0x0050F320): stage +0x10 (word) = 0xFFFF; sampler name +0x14 an empty narrow `std::string`; default texture name id +0x30 = the invalid id at 0x00BF5A14 (-1). `SetStage` (0x0050F0C0) stores the word. `SetSamplerName` (0x0050F3B0) narrows the wide string with 0x004C3AE0 (each wide character's low byte [I]) into +0x14 (0x0050F3DF..0x0050F3F4); a non-ASCII sampler name would collapse (none in the install). `SetDefault` (0x0050F0D0): only if +0x30 is still the invalid id, `+0x30 = GetOrAddId(text)` and +4 = 1 (once-only, not observable from a `.mat`, which calls it once on a fresh object). `GetDefaultName` (0x0050F100) is the name of +0x30 (callers `ApplyParamDefaults` 0x00502973 and `ObjectNodeEmitter` slot 25 0x0055B15D). **The texture's stage is the `Stage` attribute if given (not 0xFFFF), else found by `SamplerName` in the pixel shader's constant table**: `ResolveParameters` reads `GetStage` (0x0050F120, 0x005056A5, 0x00505745), and when it is 0xFFFF takes the register from the driver's slot 69 on the pixel shader with the sampler name from +0x14 (read through 0x00920030); still 0xFFFF: the parameter is skipped (render-18, phase 3). `HasSameStage` (0x0050F130, slot 9): true when this +0x10 is not 0xFFFF and equals the other's; an unassigned stage never matches, not even itself; no direct caller found [I].

## Typed parameters at draw, and what an unset parameter holds

(render-23 and render-24, read 2026-11-01; DAOParagonEngine #351; two readings reconciled; the table and the transpose [C by the reading], checked after both readings by the reconciler)

**What an unset parameter holds.** A `Parameter` the `.mao` leaves out is filled by `MaterialObject::ApplyParamDefaults` (0x005028C0) before it is ever written. It asks the object's `Has*Parameter` tests (0x004FF330 and the others, above) first; "has a value" is the art parameter's byte +4. The constructors' own values (a runtime Float's unset value, a Vector4 (0,0,0,1), a Color4 (0,0,0,0)) do not reach a register by any path read (`SetValue` never stores in the object and every caller passes its own data: 0x004F3050 the instance's value, 0x004FF7A0 the material object's, and the engine sources under 0x004F9250, for example 0x004F8970 and 0x004F8DF0); the inline value is reachable only by slot 9 (`GetValuePtr`), whose callers were not searched over the whole exe [I].

| Type | The .mao has it | The definition has a value | The definition has none |
|---|---|---|---|
| 0 Texture | kept (0x00502955) | the Default's texture (0x0050297C) | nothing set (0x0050296B); `Apply` then returns false and binds nothing (0x0050F7FD) |
| 1 Float | kept (0x00502997) | the Default (0x005029B8) | **0.0** (0x005029CB) |
| 2 Vector4f | kept (0x005029F3) | the one group when the Default holds exactly one (0x00502A23..0x00502A35), else **(0,0,0,0)** (0x00502A3F) | **(0,0,0,0)** (0x00502A6A) |
| 3 Vector4fArray | kept (0x00502AAA) | cut to Size when it holds at least Size groups (0x00502AE7..0x00502AF7); else **the Default is dropped** for a new vector of Size elements (0x00502B05..0x00502B2D) | not set, and the call returns false (0x00502B49) |
| 5 Matrix4x4f | kept (0x00502B61) | the Default (0x00502B7C) | **identity** (0x00502B80: 0x004D38E0, a static zeroed then given ones on the diagonal, 0x004D38F9..0x004D3925) |

The short array's new elements are copies of a Vector4 left unwritten on the stack (0x0046C425..0x0046C42D: `sub esp,0x10`, then the fill 0x0046C2F0): their value is whatever the stack held, so zero is an inference. A type 4 definition parameter has no row: no art parameter has type 4.

**Binding at draw** (carried over from render-23). **Port shape** (render-23's, as changed by render-24). One value type per definition parameter: Texture {stage: Option<u16>, sampler, default name}, Float {value, min, max, has_default}, Vector4 (groups), Vector4Array (groups, size), Matrix (Option). One function, cited to 0x005028C0, from a definition's parameter and a `.mao`'s value to the value a shader sees: the `.mao` value first (`Has*Parameter`), the definition only where the `.mao` has none. Float: `.mao`, else the Default when there is one, else **0.0**. Vector4: `.mao`, else the first group when the Default has exactly one, else zero. Vector4Array: `.mao`, else the groups cut to Size when there are at least Size, else Size zeros (an inference: the game's are unwritten stack bytes). Matrix: `.mao`, else the Default, else **identity**. Texture: `.mao`, else the Default's texture by name, else none (the game binds nothing; wgpu needs something bound, so keep black, marked inferred). Parsing: Float by the leading-float parse; Vector4 array by `split_whitespace`, `map_while` parse, `chunks(4)` padded with 0 (the trailing-whitespace zero element only if an array's length is ever visible; it is clamped to the shader's registers); Matrix sixteen floats in file order. Validate Floats at load (non-empty name, min <= value <= max, NaN invalid) and log invalid ones. Upload: float 4 bytes (x only), Vector4 and Color4 16, matrix 64 (transposed unless the constant is `row_major`), arrays their own length, each cut to `registers * 16`. No colour conversion in the parameter.

## The .sta builder

(render-22, read 2026-11-01; DAOParagonEngine #351; two readings reconciled, addresses [C by the reading]; the state machine and vocabularies are in `dev/FRAME_EFFECTS.md`; core's reader is DAOLib #295)

`MaterialStateBuilderXML2` (0xBC bytes, vftable 0x00AF4FBC; constructor 0x0050ED30) is the `.sta` reader. The loader (0x004FC720) appends `.xml` to the state's name (`Sky.sta` is `sky.sta.xml` in states.erf), takes `DefaultState.sta` when the name is over 0x20 characters or has invalid characters, and renames the state to the name asked (0x004FC8F9), so the file's `Name` is never used. Steps:

1. Keep a stack of open element names (+0xC). `Meta` is not pushed (`StartElement` 0x0050EE50: +0xB8 = 1 and return, 0x0050EE7C..0x0050EEA7; `EndElement` 0x0050E4F0, slot 2: +0xB8 = 0 and return, 0x0050E51D..0x0050E535; +0xB8 is read by nothing known).
2. `MaterialState` (string 0x00AF4F68, compared **without case** in StartElement by `__wcsicmp`, 0x0050EF0F): if a state exists already, return without reading attributes (0x0050EF1B..0x0050EF21); else `new 0x9C MaterialState(device(+0x20), 1)` (0x004FB6B0) into +4 and its self handle made weak (0x004FA0E0) (0x0050EF23..0x0050EF85). Then `ReadAttributes` (slot 4 here; in the `.mat` builder slot 4 is the result). Attributes of elements before the first state are ignored (0x0050DE0D).
3. `ReadAttributes` (0x0050DDE0, `ret 4`): the owning element is the stack top, compared **exactly** (0x00851E00: length, then characters) with `MaterialState`, `DeviceState`, `SamplerState`; parents are not checked, so a `DeviceState` anywhere under the root is read. **Attribute names match without case** (`__wcsicmp`): 8 core files write `value=` in lower case on their `DS_FILLMODE` line (cookiestate, fabiostate, hnstate, ldprt, ldprtstate, normalmapshadowstate, normalmapstate, parallaxstate), all FILL_SOLID, which is also DefaultState.sta's; a reader must not treat them as malformed, and core's case-sensitive `xml::Attribute` cannot be used as it stands. Per element: `MaterialState`: `Name` (0x00AEDA08) or `ID` (0x00B2BE58) to the state's +8 (0x0050C500; 0x0050E175..0x0050E1ED). `DeviceState`: `State` (0x00AF4554) to +0x24 (0x0050DE7F..0x0050DEF4), `Value` (0x00AF44BC) to +0x40 (0x0050DF98..0x0050E00D). `SamplerState`: `State` to +0x5C (0x0050DF00..0x0050DF75), `Value` to +0x78 (0x0050E017..0x0050E075), `Stage` (0x00AF4C3C) to +0xB0 as `wcstol(s, 0, 10)` (0x008E643E, 0x0050E094..0x0050E0E9), `SamplerName` (0x00AF4C24) to +0x94 (0x0050E0F4..0x0050E167). Any other attribute is ignored (0x0050E1FF).
4. At the end of a `DeviceState` (0x0050E557..0x0050E5B0): `AddDeviceState(State, Value)` (0x004FA430); the pair is kept only if both strings are known (tables 0x004F93B0, 0x004F98B0; 0x004FA453..0x004FA469).
5. At the end of a `SamplerState` (0x0050E60D..0x0050E62D): `AddSamplerState(Stage, State, Value, SamplerName)` (0x004FB8B0); then **Stage is reset to -1 and SamplerName to ""** (`Stub::ReturnMinusOne` 0x004E13D0, string 0x00ADEF14; 0x0050E632..0x0050E644). With a SamplerName the entry is by texture with stage 0; without one the stage is the number. The entry is kept when type and stage are not -1; the value is not tested (0x004FB9CF..0x004FB9E7). A sampler without `Stage` and without a texture is dropped.
6. State and Value are **not** reset between elements (+0x24 and +0x40 for devices, +0x5C and +0x78 for samplers), so an element without one inherits the previous element's. No shipped file does this (every element gives both State and Value; every SamplerState gives exactly one of Stage (1171) or SamplerName (3339)); keep it if it costs nothing.
7. Then the name is popped (0x0050E390); when the stack is empty the shared no-op 0x005BDCF0 is called on the state and the done byte +0x1C = 1 (0x0050E649..0x0050E66A). `TakeResult` (slot 5, 0x0050EFB0): done 0 gives null; else the valid byte (0x004F93A0) is read and discarded (0x0050EFF4..0x0050F006), the state moved out, +0x4 nulled, +0x1C cleared. The done byte is not initialised by the constructor (`TakeResult` before any element would read garbage; the loader parses first).

## The material manager, the preloaded materials and the weak handles

The 40 `.mat` files the renderer loads at start (`LoadStandardMaterials` 0x004F8500, list at 0x00BF5598 to 0x00BF5634), `MaterialManager::GetMaterial` and its fallback, `ReloadShaders`/`RebindMaterials`, `MaterialObjectManager` and the weak `General::SafePointer` handles it keeps are in `dev/FRAME_EFFECTS.md`, "MaterialManager: the .mat libraries, and the standard list", "MaterialObjectManager: the .mao objects" and "Weak handles". Two points from this note's readings that sharpen it: the object manager's lookup order is name + ".xml" before the plain name (above), and `Default_Miss01.mao` stands in for a missing or invalid object, while a missing `.mat` falls back to the default material (0x00C30974, the string unread: `Default_Missing.mat` [I]).

## Where the readings disagreed

- Whether a misplaced element is built and dropped (render-21) or never built (render-22): never built, StartElement makes it Unknown (0x0050D494, 0x0050D85E).
- AddSamplerState: one reading said a pair is kept only when both names are known; the exe keeps a sampler entry when type and stage are not -1 and tests both names only for the device pair (0x004FB9CF..0x004FB9E7, 0x004FA453..0x004FA469).
- The end test of the Vector4 array Default (0x0050F5BD, 0x0050F62B): one reading a short last group is padded, the other trailing whitespace adds a zero element; both follow from the loop and both are kept.
- What an unset parameter holds: both readings of render-23 and render-24 first took the constructors' values (a Float 1.0, a Vector4 (0,0,0,1)) as the default; no path writes them to a register, and `ApplyParamDefaults` (0x005028C0) gives 0.0, zero and identity (table in "Typed parameters").
- The record byte +0x28: render-23 called it a register set; it is the column-major flag (0x00505968, 0x0087B358..0x0087B368), and RegisterSet goes to +0x1C.

- The default semantic: one reading took "the first, or one with an empty name", the other "the one named Default, else the first". Settled in the disassembly (0x0050359E..0x005035B5): the name compared is the global "Default" (0x00C31108), and a list that was empty. The second reading is right.
- Who a valid byte belongs to (0x004F6A70) and whose id (0x004F6A90): both are folded getters shared by Material and MaterialSemantic; the walks that use them (0x005032A8, 0x0046E367) read semantics.
- Whether a pass's "current pass" cache (0x00C30990) skips binds: it does not; the only writes are zeros (0x00459950, 0x00527323), so every draw binds both shaders and the full state. Not a material rule, listed because both readings of `Apply` (0x00506550) differed.
- Whether an `EffectParameter` outside a pass is deleted: it is not (0x0050CBC9).
- The object manager's file order: the readings of the object manager agreed with the exe (".xml" first); `dev/FRAME_EFFECTS.md` said otherwise and is corrected.
- `MaterialEffectPass`: whether the named stages are played. One reading said yes; the pass loader replaces the list (0x0050B1BB, 0x00505EC0).
- The `RequiresID` substitute: one reading had Default_Black unless a renderer option; the other a global name. Settled to `Default_Black`, or `default_missing` when the graphics object's byte +0x114 is set (0x00500E9E).
