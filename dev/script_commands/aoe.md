# Script commands, group "aoe": the GOG exe's handlers

Read 2026-10-18 by lib-agent-2 (a subagent) in `game\DAOrigins.exe` (GOG 1.05, base 0x400000) with `tools\daoexe.py --disasm`, for DAOParagonEngine #27. Not seen in play. "(checked)" = read in the disassembly; "(inferred)" = not.

Shared facts:
- Handlers are `__thiscall (commandId, paramCount)`, `ret 8`, on `CVirtualMachineCommands`; a failed pop returns -639, a failed push -638 (master's `dev/script_commands/commands.md`). Its +8 is OBJECT_SELF (`effect_access.md`). (checked)
- **The area-of-effect object** is `CCAreaOfEffectObject` (0x4F0 bytes, vftable 0x00B23854; its cast is vtable slot 3, +0xC, `dev/object_casts.csv`). It is made only by the native `EFFECT_TYPE_AOE` (5) apply handler 0x007A0230 (master's `dev/COMBAT.md`, "The death effect" table): creator (+0x4AC) = the effect's creator, the row of `VFX Persistent` (table 96, `persistent.gda`) = the effect's int 0, ability (+0x4D4) = the effect's ability, its event script = the effect's string 0, stationary (+0x4A4) = 1 when applied at a location, 0 when on an object. (checked)
- **Layout**, from its save (0x007E4C70) and the GFF4 labels (`dev/gff4_fields.csv`): +0x4CC row (16603 `SavegameAOEID`), +0x483 shape byte (16604), +0x468 radius, +0x46C width, +0x470 length (16605–16607, floats), +0x4AC creator (16608), +0x4B8 duration in ms (16609), +0x4BC duration type (16610), +0x4C4 linked (16611), +0x4D4 ability (16750), **+0x4DC flags (16751)**, +0x4A4 stationary (16752). +0x118 is the object it is attached to, +0x49C the id of the effect that made it, +0x4D8 "first heartbeat pending". The constructor tail (0x007E6093) zeroes +0x4C0, +0x4C4, +0x4D4, +0x4DC and sets +0x49C to -1. (checked; +0x118 and +0x49C's meaning inferred from 0x007E4A50 and 0x007E64D0) Every use of the owner is +0x118 (0x007E4A50, 0x007E4AF0, slot 87 0x007E6410, 0x007E5D80, 0x007E64D0); the decompiler's `offset_0x114` member is 4 short (paragon-agent-2, 2026-10-30).
- **Shape.** `0x007E4DA0` reads the row's `Shape`: "C" → shape 'S' (0x53) with `Radius`; "R" → 'R' (0x52) with `Width`/`Length` (corners kept at +0x4C8). Any other string sets no shape. Containment (slot 96, +0x180, 0x007E4810): the point must be within the 3D distance +0x468 of the centre (+0x120) first; then 'S' → inside, 'R' → inside when on the inner side of all four edges (2D cross products), any other shape → outside. (checked) A rectangle's corners (0x007E60D0 → 0x007E4730, four times) are the local (±L/2, ±W/2) turned by 0x004EDF80, which takes +Y to the orientation at +0x130 (−sin a, cos a, 0), so the length lies across the facing and the width along it; its radius (0x007E4920) is sqrt((W/2)² + (L/2)²) (read 2026-10-30 by paragon-agent-2).
- **Enter and exit.** The scan 0x007E5950 runs when the AOE joins an area (0x007E63F9, which also adds its id to the area's +0x1C0 list), when it moves (SetPosition, slot 31 at +0x7C, 0x007E64A0, at 0x007E64C6; the decompiler's vfunction32) and when it is re-attached to its owner (0x007E5D80). It walks the area's objects near the centre; only object type byte 6 (cast to `CCCreature`, slot 0x10) that is active (slot 0x6C, 0x00699FA0) and not dead counts. A creature inside and not yet listed gets the AOE's id pushed onto its **+0xBA8** vector and an ENTER; one listed and now outside is taken off and gets an EXIT. (checked) The creature's own movement is checked too (A creature walking in, below).
- **The ENTER/EXIT event** (0x00698850, `__thiscall (bEnter, creator, creatureId, ability, bNow)`, `ret 0x14`): type 8 `EVENT_TYPE_ENTER` or 9 `EVENT_TYPE_EXIT`, creator (+0x24) = the AOE's creator, target (+0x28) = the creature, int 0 = the ability, object 0 = the AOE. It goes to the **AOE's own script** (`AIMaster::AddEventDeltaTime(0, 0, creature, aoe, 10, event)`, or at once through slot 50 when bNow). It is skipped while the area's +0x234 is set, and when the AOE's +0x28C set holds that event type (0x00698490). (checked; what +0x28C means is inferred: events filtered) The area's +0x234 is set at 0x0068B36D while the area reads its save record and cleared in UpdateAreaListSwap's state 0xC (0x006C8DFC) (read 2026-10-30 by paragon-agent-2). The creature-side senders pass bNow = 0; the destroy's EXIT passes 1.
- **Heartbeat and duration** (the AOE's update, 0x007E4AF0): if +0x4C4 is set it is placed at its attached object's position and area, then +0x4C4 cleared. The first update with +0x4D8 set builds `EVENT_TYPE_AOE_HEARTBEAT` (74; creator +0x4AC, object 0 the AOE, int 0 the ability) and runs its script at once; later heartbeats are the scripts' own `DelayEvent` (`dev/TURN_BASED.md`). For duration type 2 (TEMPORARY) it subtracts the frame's milliseconds from +0x4B8 and destroys itself (slot +0x198, `DestroyObject(0)`) when no time is left. Then its effects and commands step. (checked) Its handler for AI event 11 (0x007E4A50) removes effect +0x49C from the attached object's or area's effects holder. (checked; that 11 is destruction is inferred)
- **An attached AOE is carried by an area change only** (read 2026-10-30 by paragon-agent-2): only a creature owner registers the AOE in its +0xB98 list (0x007E64D0), and only 0x006B3070 (`AddToArea` 0x006B6BC0 and the jump commands) loops over that list and runs the re-attach 0x007E5D80, which takes the AOE off the creature's +0xBA8, sends the listed their EXIT (0x007E5560), sets its position, lists it again and scans. The owner's walking does not move it. After a load the owner's effect re-attaches it through 0x007A0230 (at 0x007A0360, +0x118 == -1), then slot 87 and the update run slot 62 at the owner.
- **A creature walking in** (read 2026-10-30 by lib-agent with a subagent, for DAOParagonEngine #322; not seen in play). A stationary AOE or a trigger is entered from the creature's side: `0x006AE100(newSet)` on `CCCreature`, called by `0x006B2F70(oldPos, newPos)` and `0x006B3070(pos, areaId)`. The first runs from the creature's `SetPosition` 0x006B5EF0 (force 0; `CCObject::SetPosition` 0x00695540 returns early on an equal position, so every frame the position changed), from `SetActive` 0x006B5D90, the revive in 0x006BC4B0 and death (slot 0x78, 0x006B3620); the second from `AddToArea` 0x006B6BC0, `RemoveFromArea` 0x006B6E60 (area -1) and the jump commands. Neither the AOE's update nor the trigger's (0x00798DB0) scans anything. (checked)
  - **The set:** `0x0073EFE0(area, pos, out)` walks the area's **+0x1C0** id vector, which holds every AOE (added at 0x007E63C6) and every trigger but the reverb and volume audio ones (`dev/AUDIO.md`), with no radius cull, and keeps each object whose containment (+0x180) holds for the creature's **new position as a point**, not the segment moved, so a thin AOE or trigger can be stepped over in one frame. The AOE's test is 3D (above, Shape); a trigger's (0x00799130) is x and y only, an even-odd crossing count over its outline (vertices at +0x490, 16 bytes each, count +0x494, index ring +0x498). The set is empty when the creature has no area, is not active (slot 0x6C, 0x00699FA0) or is dead (slot 0x1D0); party, hostility and stealth are not tested. (checked)
  - **The diff:** ids in the creature's **+0xBA8** not in the set get vtable +0x17C(0, ...) (EXIT), then ids in the set not in +0xBA8 get +0x17C(1, ...) (ENTER), then +0xBA8 becomes the set. So +0xBA8 is one record for AOEs and triggers alike; a trigger keeps no list of who is inside. The events are queued (bNow = 0). EXIT follows death, going inactive, leaving the area and the creature's destruction, each through the same call with an empty set. (checked)
  - **The event:** an AOE's +0x17C is 0x007E4A30, a stub that puts the AOE's creator (+0x4AC) and ability (+0x4D4) in the arguments and jumps to 0x00698850, so the creature is the target only. An AOE's ENTER is withheld while the creature takes part in the running conversation (0x006A2960: game mode 4 and 0x0068CC30), though its id is listed (IsInAOE, below). A trigger's +0x17C is 0x00799850 (`dev/AUDIO.md`): type 8 or 9 to the trigger's script, creator and target both the creature, object 0 the trigger. (checked)
  - **The AOE's destroy and its effect's remove:** the effect's remove handler 0x007A0520 runs first: it sets AOE +0x49C = -1, calls slot +0x198 (0x00696A60: byte +0x2BD, queues AI event 11) and removes the effect at once (0x007A0150). Event 11 reaches `CCObject::EventHandler` (0x00698B41), which calls slot +0xFC (0x007E5670) and so 0x007E5560: each creature of the area's +0x680 vector inside the shape and listed in +0xBA8 has the id erased and gets EXIT at once (bNow = 1). Destroying the AOE first goes through event 11 with +0x49C ≥ 0, whose handler 0x007E4A50 removes the effect (0x007A1740, which reaches 0x007A0520 [inferred]), and a second event 11 sends the EXITs. So in both orders the effect is gone before the EXIT. A creature listed but no longer inside the shape gets no EXIT there. (checked)

### GetAOEFlags (334)
- **Handler:** 0x00668A20, shared `ScriptCommand::GetObjectProperty` (with GetObjectActive 141, GetEffectsFlags 192, GetObjectInteractive 677 and more); the case is the last cast block, at 0x00668CA7–0x00668CBC. (checked)
- **Does:** pops the object (and, only when paramCount > 1 or > 2, one or two ints, not used here), `GetObjectById`, casts through vtable slot 3 (AOE). For an AOE and command 0x14E it pushes the int at **+0x4DC** raw. (checked)
- **State:** `CCAreaOfEffectObject` +0x4DC, the flags; 0 at construction, saved as `SavegameAOEFlags` (16751) and loaded back (0x007E537F). (checked)
- **Edge cases:** an invalid id or any object that is not an AOE (a creature falls through its own cases) pushes 0; the script does not fail. (checked)
- **The bits:** the engine gives them no meaning: in the AOE class's code (0x007E3000–0x007E8000) +0x4DC is touched only by the constructor, save and load (checked; the rest of the exe not searched for the offset). The scripts use one bit, `AOE_FLAG_DESTRUCTION_PENDING` 1 (`aoe_effects_h.nss`), for grease set alight once (`IgniteGreaseAoe`, `spell_grease.nss`). (checked in the scripts)

### SetAOEFlags (335)
- **Handler:** 0x0066BE50, shared `ScriptCommand::SetObjectProperty`; the AOE block at 0x0066C0EE–0x0066C115. (checked)
- **Does:** pops the object, then nFlags when paramCount > 1 (else 0), `GetObjectById`, casts through slot 3; for an AOE and command 0x14F writes nFlags to +0x4DC. Nothing else: no event, no rescan, no masking. (checked)
- **State:** +0x4DC, as above. (checked)
- **Edge cases:** an invalid or non-AOE object does nothing; returns 0. Any int is stored whole. (checked)

### IsInAOE (336)
- **Handler:** 0x0066E040, shared with IsPerceiving (170); the branch on command 0xAA at 0x0066E08E. (checked)
- **Does:** pops oCreature, then oAOE. `GetCreatureById(oCreature)`; for 336 calls 0x006AE2B0 (`creature+0xBA8`'s `std::vector<unsigned int>::Contains(oAOE)`) and pushes the byte result. (checked)
- **State:** the creature's +0xBA8, the AOEs it is listed in, kept by the scan above. So TRUE means "has been entered and not exited" as the engine last scanned, not a geometric test now. (checked)
- **Edge cases:** oCreature not a creature (a placeable, invalid) → FALSE. oAOE is not looked up: an invalid or non-AOE id is simply not in the list → FALSE. Neither fails the script. (checked) An AOE of any shape lists a creature without sending ENTER while the creature takes part in the running conversation (0x006A2960, A creature walking in), so IsInAOE can be TRUE for a creature the script never saw enter. (checked)

### SetIndividualImpactAOEEvent (845)
- **Handler:** 0x0065C580 (not shared). It calls `CScriptEvent::CScriptEvent` (0x0069BAC0), `CDataArrays::SetInteger/SetObject/SetFloat/SetString`, the CRT's rand (0x008E6A8E, inferred) and `AIMaster::AddEventDeltaTime` (0x0064ACE0). (checked)
- **Does:** pops oCaster, oTarget, nAbility, lTarget (engine structure 1), and nBaseDelay only when paramCount ≥ 5 (else 0). Builds event type 1066 (`EVENT_TYPE_SPELLSCRIPT_INDIVIDUAL_IMPACT`): creator = OBJECT_SELF, int 0 = nAbility, object 0 = oCaster, object 1 = oTarget; for a non-null location object 2 = its area (+0x20) and floats 0–2 = its position (+0, +4, +8); string 0 = **the running script's name** (the VM's per-level name, `[vm+0x64]·0x240 + vm + 0x288`). Queues it with `AddEventDeltaTime(0, nBaseDelay + rand() % 150, self, self, 0x1D, event)`. (checked)
- **Delivery:** AI event 0x1D in `CCObject::EventHandler` (0x00698A50, at 0x00698B2D) stores the event as the object's current event (+0x2A8) and runs **the script named in string 0** on the object, not its event script. So the calling spell script (`spell_aoe_instant`, `spell_cone`) is re-run on OBJECT_SELF with the event, 0–149 ms + nBaseDelay later, and reads it back as `spell_aoe_instant.nss` does. (checked)
- **State:** the AI master's event list (`AIMaster`, client app +0x1AC; `src/dao/Addresses.h`). (checked)
- **Edge cases:** nothing is validated: oCaster and oTarget are stored as given, any nAbility. An invalid OBJECT_SELF leaves the event with no target, freed by `DeleteEventData` when due (inferred from `ProcessEvent` 0x0064A8C0). A null location sets no area or position (0.0 floats when read). A negative nBaseDelay is passed as unsigned milliseconds (a sum below 0 wraps to a huge delay; inferred). With no AI master (client app +0x1AC null) the event is neither queued nor freed (checked that there is no free). Returns 0.
